# oh-my-SRE 제품·아키텍처 PRD

상태: 초기 프론트엔드 프로토타입. 기준일: 2026-10-21. 독자: 제품·프론트엔드·백엔드 엔지니어.

**핵심 결정: 사람의 판단을 돕는 작은 인터페이스를 먼저 만들고, 관측·추론·실행 환경·인증을 교체 가능한 경계로 둔다.**

## 1. 문제와 현재 범위

[합의 목표] 운영자는 새 알림의 양보다 지금 판단할 일, 조사 근거, 모르는 점, 다음 행동을 알고 싶다. 모델 실행·관측 갱신·사건의 실제 진전은 서로 다르다.

[현재 구현 범위] 공개 프론트엔드는 새로 작성한 합성 사건만 사용한다. 실제 수집·모델·외부 알림·인증·운영 승인·복구 백엔드는 연결하지 않는다. 데모 판단은 현재 브라우저 메모리에서만 바뀌며 새로고침으로 초기화된다. 비공개 운영 데이터·문서·코드를 포함하지 않는다.

시각·상호작용 정본은 루트 `DESIGN.md`다.

## 2. 전체 흐름과 책임

```text
[현재] 합성 사건 데이터 -- 화면 데이터 --> 판단함
                                           |
                                      사용자가 선택
                                           v
                  다섯 문장 + 근거 + 최신 이력
                                           |
                          데모 판단 기록(메모리만)

[제안] 관측 어댑터 --> 검증된 증거 --> 사건·조사 코어 --> 화면 projection
                                         |
                                    읽기 전용 조사
                                         |
                                조치 제안 + 불확실성
                                         |
                                별도 사람 승인·감사
                                         |
                              외부 수동 실행·회복 검증
```

위에서 아래로 현재 데모와 미래 경계를 구분해 읽는다. 화살표는 데이터 전달 또는 사용자 선택이며 자동 실행 권한을 뜻하지 않는다. 현재 구현의 외부 운영·모델 API 호출 0과 데모 판단 상태 전이로 검증한다.

| 경계               | 소유                                              | 금지                                              |
| ------------------ | ------------------------------------------------- | ------------------------------------------------- |
| 관측 연동          | source·관측 창·조회 범위·freshness·receipt 정규화 | 빈 결과를 정상으로 바꾸기, credential을 UI로 전달 |
| 추론 모델          | 제한된 증거를 받아 가설·불확실성·비용 결과 생성   | 모델 동의로 운영 권한 발급                        |
| 에이전트 실행 환경 | 작업·재조사·예산·시도 상한·취소 관리              | 실패를 성공으로 재해석, 무제한 재시도             |
| 인증               | 공급자 공식 인증과 조직·역할 검증                 | 구독 로그인과 범용 API 권한을 동일시              |
| 사람 판단          | 구체 제안 검토·보류·감사 기록                     | ACK나 검토 완료를 실제 실행·회복으로 표시         |
| 프론트엔드         | 근거 있는 projection과 선택·필터·상세 표시        | 비밀 저장, 실제 연결 없이 성공 가장               |

## 3. 사건과 우선순위 계약

[제안] `Case`의 ID는 내부 사건 식별자이고 표시 severity와 조사 상태를 분리한다. 원천 경보 등급만으로 사람 긴급 호출을 확정하지 않는다. 비용 한도·재시도 횟수·장기 지속 기준은 연결 환경별 정책이며 이 데모의 합성 숫자는 운영 기준이 아니다.

```json
{
  "kind": "synthetic",
  "id": "case-01",
  "priority": "P1",
  "needsDecision": true,
  "investigation": "waiting_for_human",
  "evidenceStatus": "partial",
  "recovery": "unverified"
}
```

판단함에는 구체적인 사람 결정이 있는 사건을 먼저 표시한다. `unknown`·관측 부족·예산 소진만으로 사람 결정 항목을 만들지 않는다. 관측 부족은 확인된 장애와 구분하고, 최신 사건 정보와 과거 조사 가설을 섞지 않는다. 검토를 완료해도 `recovery`는 바뀌지 않는다.

## 4. 핵심 시나리오

### 4.1 근거가 있는 사람 판단

[설명용 합성 예시] 이벤트 처리 지연과 제한된 조치 제안이 있다. 판단함에서 선택하면 상황·확인·미확인·다음 행동·필요한 결정이 보인다. 근거 시각과 최신 이력으로 설명을 대조하고 과거 기록은 요청할 때 펼친다. 사용자가 데모 검토를 완료하면 판단함에서 제외되지만 전체 목록과 미확인 회복 상태는 유지한다.

검증: 필터 수, 사건 상세, 더 보기, 검토 기록, 목록 복귀, 외부 운영·모델 API 호출 없음.

### 4.2 관측이 부족한 사건

[설명용 합성 예시] 다음 관측이 아직 도착하지 않았다. 화면은 정상·유실·회복을 확정하지 않고 미확인 이유와 다음 확인 조건을 표시한다. 사람 판단 요청을 자동 생성하지 않는다. 미래 코어는 공백의 지속·범위 확대·회복처럼 의미 있는 변화로 알림을 판단한다. 실제 반복 스케줄러와 외부 알림 억제는 현재 구현 범위 밖이다.

검증: 조사 상태 필터에 표시되고 기본 판단함에는 없으며, 상세에서 미확인이 보인다.

### 4.3 조사 예산이 끝난 사건

[설명용 합성 예시] 모델 조사 예산을 소진했다. 이전 근거를 보존하고 왜 멈췄는지와 재개 조건을 말한다. 실패나 예산 중단을 성공·사람 승인 요청으로 바꾸지 않는다. 미래 재조사는 새 증거·악화·정책상 장기 지속과 예산 검사를 함께 통과해야 한다.

검증: 예산 대기 문구, 기존 근거, 사람 판단 없음, 모델 호출 없음.

## 5. 공급자와 인증

[현재] 연결 안내는 관측 도구, 모델 공급자, 인증 방식을 구분한다. API 키를 입력·저장·전송하지 않는다. 공급자를 고르면 요구사항 설명만 달라지며 연결 성공을 만들지 않는다.

[제안] 추론 어댑터와 에이전트 실행 환경을 별도 인터페이스로 둔다. OpenAI·Anthropic 등 API 공급자와 구독 기반 CLI 실행 환경은 같은 계약이 아니다. 구독 인증은 해당 공급자가 공식 허용한 실행 경로와 조건을 확인한 뒤 지원한다. 비밀은 서버·실행 환경의 secret store가 소유하고 프론트엔드는 상태만 읽는다.

실제 제품 인수 전에 두 번째 공급자와 별도 설치 환경으로 호환성을 검증한다. 구체 API·secret store·조직 인증은 미결정이다.
