# OpenCode 기반 SDS 전환 계획

기준: 공개 main `cbbe06af6b9888ecfb6903f65f020dc746260da7`. 동작을 보존하면서 시각 계층과 제품 문구를 교체한다.

1. 기존 6개 사용자 흐름을 데스크톱·모바일 12개 E2E로 먼저 고정한다.
2. 공식 OpenCode의 색·시맨틱 테마·타입·간격·기본 reset과 필요한 컴포넌트 CSS를 출처와 함께 보존한다.
3. Radix Themes와 Theme 스타일을 제거한다. React의 상태·제품 흐름은 유지하고 Dialog의 비시각 접근성 동작만 별도 primitive로 연결한다.
4. 공통 상태·우선순위·명칭을 정본으로 두고, 웹 색·표현과 터미널 테마·문자를 파생한다. 실제 TUI 실행기는 이번 범위에 넣지 않는다.
5. 화면 CSS를 새로 정리해 upstream 컨트롤의 색·크기·타입·border가 실제 적용되게 한다. 제품 문구는 짧은 명사형·행동형으로 통일한다.
6. 기존 동작 E2E, 토큰 파생·dark 매핑, 타입·lint·format·build, 실제 브라우저 이미지로 검증한다.
7. 출처·라이선스·공개 파일과 시각 검토 뒤 전용 브랜치만 게시한다. main 병합은 별도다.

공식 UI의 원본 Solid 컴포넌트와 React 이식 컴포넌트를 구분한다. OpenCode 제품 엔진·로고·마케팅 이미지·조직별 설정은 포함하지 않는다.
